# 理解力测试 · Round 7（路由可达性压测 / routing reachability）

> Round 6 把瓶颈从"读懂"（Layer 2）搬到了"路牌"（Layer 1：路由器 + 指针）。Round 7 就给**路牌**做一次**量化压测**——不再抽 1-2 条撞运气，而是**一次打 54 条"真实世界里的混乱说法"**，量"命中正确页"的比例。
> 数据：`qa/eval/routing-reach.json`；运行器：`qa/eval/run_routing_reach.py`（直接调用 resolver 同款打分器 `tools/router_match.rank`）。日期：2026-10-10。

---

## 1. 怎么打的（8 类真实混乱说法）

| 类别 | 模拟的是什么 | 例子 |
|---|---|---|
| normal | 正常说法（对照组） | 「老板让我周末加班怎么办」 |
| typo | 错别字（同音/形近，1 字之差） | 「面视好紧张怎么办」「怎么拒决推销电话」 |
| abbrev | 缩写 / 中英夹杂缩写 | 「MBTI 怎么看人」「怎么回老板的wx」 |
| voice2text | 语音转文字（同音字、无标点） | 「我没事他到底啥意思」 |
| ellipsis | 半句话 / 极短 | 「已读不回」「他什么意思」 |
| colloquial | 口语 / 情绪化俚语 | 「老板又画大饼了」「我妈天天催婚烦死了」 |
| mixed | Manglish / 语码转换 | 「where got 是不是在骗我」 |
| crosslang | 用英文 / 马来文问中文库的内容 | 「cara nak cakap tak nak」 |

判分：一条算"命中"，当且仅当 **resolver 解析出的主题 == 预期主题**。

**改前暴露的失败，全部是"路牌"病，没有一条是"读不懂"**——和 Round 6 的结论一致，这次把它量化了。

---

## 3. 四类真实病灶（改前 15 条 miss 归纳）

1. **CJK 错别字直接断路**（typo/voice2text 最惨）：只要触发词里一个字打错（面视≠面试、拒决≠拒绝、意事≠意思），子串匹配立刻失效 → **死路**。这是"路牌"最脆的一环。
2. **概念页抢了引擎的活**（voice2text）：`c1`（潜台词概念）和 `p2`（解码引擎）**共享 14 个触发词**（你开心就好 / 随便 / 都行 / 暗示…），而 `c1` 排在前面 → 每次打平都由概念页获胜，用户要的"解码"引擎反而被挤掉。
3. **口语/跨语同义词缺失**：`啥意思 / 谈价 / 女朋友 / 姐妹 / tak nak / borrow money / grieving` 这些**真实用词**根本不在任何触发词表里。
4. **简称与语境重叠**（abbrev/normal）：`谈价` 同时挂在 c2（说服）和 sc10（谈判）；`同事的请求` 在 sc1/sc4 之间打平——这类是**概念/场景天然重叠**，不全是 bug。

---

## 4. 据此做的升级

| 升级 | 针对 | 落地 |
|---|---|---|
| **引擎平局优先（限非泛化触发词）** | c1 抢 p2 | `tools/router_match.py` 排序键改 `(-score, -prio, order)`；`_prio` 只在"引擎靠**非**泛化词打平"时生效（避免 `已读不回是什么意思` 被 `什么意思` 抢走） |
| **CJK 错别字兜底（仅死路时）** | 面视/拒决 类断路 | `_fuzzy_hits`：**只在零命中时**启用，对长度 ≥2 的 CJK 触发词做**编辑距离 ≤1** 的窗口匹配；拉丁词不参与；加 `_FUZZY_STOP` 泛化词黑名单防 `怎么办≈怎么回` 误伤 |
| **c1 触发词瘦身（消除双挂）** | c1 抢 p2 | `router.json`：c1 删掉 `你开心就好 / 开心就好 / 随便 / 都行 / 无所谓 / fine / whatever / up to you / 看着办 / 行吧 / 再说吧 / 改天 / 呵呵 / 嗯`（这些是"解码样例"，归属 p2） |
| **同义词扩充** | 口语 / 跨语 miss | `router.json`：p2 +`啥意思/代表什么`；sc2 +`女朋友/男朋友/女友/男友/哄/追女生/暗恋`；sc6 +`借钱不还/姐妹/坏话/八卦/friend/borrow money/lend money`；sc10 +`谈价/议价/报价/讨价还价`；sc13 +`邻居/噪音/纠纷`；sc16 +`安慰/comfort/grieving`；sc4 +`婉拒/推掉/decline/tak nak/tak mahu` |
| **索引携带引擎标记** | 平局优先要能识别引擎 | `tools/build_router_index.py`：entries 加 `"eng":1`（仅 playbook）；`router_match._eng` 同时兼容 `router.json`（看 `type`）与 index（看 `eng`）——**修好一个隐患**：smoke/reach 用 `router.json`、resolver 用 `router-index.json`，两边字段不同会导致"门禁和线上行为不一致" |

> 关键设计取舍：**兜底只走死路**（零命中才触发），所以它**不可能**改变任何已经能命中的结果 → 门禁 32/32 不受影响；宁可少抓，不误伤。

## 5. 剩余 4 条 miss（判为"邻接 / 天然歧义"，非 bug）

| 例 | 期望 | 实际 | 判定 |
|---|---|---|---|
| 怎么拒绝同事的请求 | sc4 | sc1 | **sc1/sc4 打平**——"同事"给语境、"拒绝"给动作，二者都对；真歧义 |
| 潜台词是什么意事 | p2 | c1 | 错别字打断了 p2 的"什么意思"，只剩 c1 的"潜台词"——**邻接**（概念 vs 引擎） |
| 面视好紧张怎么办 | sc8 | cu2 | "面视"与"面试""面子"都是 1 字之差——**2 字 CJK 天然歧义**，无上下文无法裁决 |
| 怎么跟甲方谈价 | sc10 | c2 | "谈价"同时挂在 c2（说服）和 sc10（谈判）——**概念/场景重叠** |

这 4 条都不是"读不懂"，而是**路由标签本身有二义**；要消掉得引入更重的上下文模型，收益递减，暂不追。
